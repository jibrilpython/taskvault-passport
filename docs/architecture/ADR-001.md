# ADR-001: local-first клиент и модульный монолит синхронизации

**Статус:** принято  
**Дата:** 2026-09-29  
**Контекст:** лабораторная 2 (архитектурный паспорт), продолжение аудита Todoist / Notion Mobile / Obsidian.

## Контекст

Нужен персональный планировщик с офлайн-работой, несколькими устройствами и общим API. Команда — два человека. Нельзя повторить провал Notion Mobile (гидратация сессии на UI-потоке, WebView как источник истины). Нельзя ограничиться только файлами, как Obsidian: нужны учётные записи, устройства и контролируемая синхронизация.

## Решение

1. **Клиент — local-first.** SQLite (WAL) — рабочая копия. UI читает только локальную БД. Сеть не блокирует список задач.
2. **Сервер — модульный монолит.** Один процесс, модули `identity`, `catalog` (проекты/задачи/метки), `sync`. Общая PostgreSQL. Никакой сетки микросервисов на старте.
3. **Синхронизация — дельта + идемпотентные команды.** Клиент шлёт `POST /v1/sync` с UUID команд (create/update/complete). Сервер отвечает набором изменений после `sync_token`. Конфликт: last-write-wins по `updated_at` сервера + клиентский `client_clock`; жёсткие конфликты (два параллельных переименования) отдаются в `conflicts[]` для UI.
4. **Исходящие команды — outbox.** Запись в `outbox_command` в той же транзакции, что и локальное изменение. Фоновый воркер отправляет пачку. Это аналог transactional outbox без отдельного брокера.
5. **Auth.** Bearer JWT. Устройство (`device`) привязано к пользователю; `sync_cursor` хранится на пару user+device.

## Отклонённые варианты

| Вариант | Почему нет |
|---------|------------|
| Гидратация сессии + WebView как у Notion Mobile | UI-поток, потеря данных при обрыве; противоречит аудиту лаб. 1 |
| Микросервисы + брокер с дня один | Операционная стоимость выше выгоды при одном bounded context |
| Только Markdown-свод, как Obsidian | Нет модели пользователя, ACL, идемпотентных команд |
| Классический CRUD без sync_token | Полные выборки, гонки, плохой офлайн |

## Последствия

- Контракт API должен содержать `SyncRequest` / `SyncResponse`, не только REST-коллекции.
- ER обязана включать `outbox_command` и `sync_cursor`.
- Монолит можно разрезать позже по уже прочерченным модулям, не переписывая клиент.
